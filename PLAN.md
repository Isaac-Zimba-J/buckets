# PLAN — notifications, SMS auto-sense, bills, to-buy delete, Home recent

Root causes (verified by reading the code):
- A. Notifications repeat: every re-plan (`NotificationSync`, also on app resume) calls `show()` again for anything due now (payday slot 0 at `now`, alerts, income, ended wishes). Tapping a notification resumes the app -> re-plan -> shown again. Payday slots are anchored to `now`, so their IDs/times shift each run.
- B. SMS never captured: `AlertConfig.allowedPackages` lists only the MoMo/Airtel apps, no SMS apps. Listener also prepends the notification title (`title\nbody`), but every template is `^`-anchored on the body, so nothing could parse. Ingest only runs on start/resume, so nothing logs while the app is open.
- C. Bills hidden: before the first payday the cycle is `[setup, first payday)`, so bills due earlier in the month get no occurrence until the next cycle.
- D. To-buy: no delete exists at any layer.
- E. Home recent: the first-run Home state (before first payday) has no recent-transactions list at all.
